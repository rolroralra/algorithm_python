# BFS (너비 우선 탐색, Breadth-First Search)

> 구현: [`bfs.py`](./bfs.py) — `bfs()` 함수
> 관련 테스트: [`test_bfs.py`](../../tests/bfs/test_bfs.py)

## 1. 왜 BFS가 필요한가?

"나와 어떤 사람 사이에 친구의 친구를 몇 명이나 거쳐야 하는지" 궁금했던 적이 있나요? 이른바 "케빈 베이컨의 6단계 법칙"처럼, 그래프에서 "몇 단계(hop)만에 도달할 수 있는가"를 알고 싶을 때가 많습니다.

- SNS에서 "나와 2촌 이내인 친구 추천하기"
- 미로에서 출발점부터 도착점까지 "최단 칸 수"로 가는 길 찾기
- 네트워크에서 라우터 몇 개를 거쳐야 목적지에 도달하는지 계산하기

이런 문제들의 공통점은 **간선(edge)에 가중치가 없다면(또는 모두 동일하다면), 가장 가까운 것부터 순서대로 탐색해야 최단 경로를 보장할 수 있다**는 것입니다. 이를 가능하게 해주는 것이 BFS입니다.

BFS는 마치 호수에 돌을 던졌을 때 물결이 퍼져나가는 모습과 같습니다. 출발점을 중심으로 "1단계 거리에 있는 노드들"을 모두 방문한 뒤, 그다음 "2단계 거리에 있는 노드들"을 모두 방문하는 식으로 **레벨(level) 단위로 퍼져나가며** 탐색합니다.

```
        (시작)
          0            <- 0단계 (거리 0)
         / \
        1   2          <- 1단계 (거리 1)
        |   |
        3   4          <- 2단계 (거리 2)
```

이 순서(0 → 1,2 → 3,4)대로 방문하기 때문에, 무가중치 그래프에서 BFS가 어떤 노드를 "처음 방문하는 순간"의 깊이가 곧 시작점으로부터의 최단 거리가 됩니다.

## 2. 핵심 아이디어: 큐(Queue)를 이용한 레벨 단위 탐색

레벨 단위로 퍼져나가려면 "먼저 발견한 노드를 먼저 처리"해야 합니다. 즉 **FIFO(First In First Out)** 구조가 필요하고, 이것이 바로 큐(Queue)입니다.

**코드 연결**: `bfs.py:1`에서 `collections.deque`를 큐로 사용합니다. 일반 `list`의 `pop(0)`은 앞의 원소를 지우기 위해 나머지 원소를 전부 한 칸씩 당겨야 해서 `O(n)`이 걸리지만, `deque.popleft()`(`bfs.py:10`)는 양쪽 끝에서의 삽입/삭제가 모두 `O(1)`입니다. 큐를 빈번하게 넣고 빼는 BFS에서는 이 차이가 성능에 직접 영향을 줍니다.

## 3. 코드로 보는 BFS 동작

아래 그래프(테스트 코드 `test_bfs.py:11`에서 사용하는 그래프와 동일)로 동작을 추적해봅니다.

```
graph = [[1, 2], [0, 3], [0, 4], [1], [2]]

        0
       / \
      1   2
      |   |
      3   4
```

| 단계 | 큐 상태(처리 전) | pop한 노드 | 새로 push된 노드 |
|---|---|---|---|
| 1 | `[0]` | 0 | 1, 2 |
| 2 | `[1, 2]` | 1 | 3 |
| 3 | `[2, 3]` | 2 | 4 |
| 4 | `[3, 4]` | 3 | (없음) |
| 5 | `[4]` | 4 | (없음) |

최종 방문 순서: `0 → 1 → 2 → 3 → 4` (레벨 순서 그대로).

### 방문 체크는 "꺼낼 때"가 아니라 "넣을 때" 한다

`bfs.py:19`를 보면 `is_visited[next_index] = True`를 큐에 **push하는 시점**(`bfs.py:18` 바로 다음)에 실행합니다. 왜 pop할 때가 아니라 push할 때 표시할까요?

만약 push할 때 표시하지 않으면, 같은 노드가 아직 큐 안에 있는 상태에서 다른 경로를 통해 또 큐에 들어갈 수 있습니다. 예를 들어 노드 0이 1과 2 모두와 연결되어 있고, 1과 2가 동시에 3을 가리킨다면, 3이 큐에 중복으로 쌓이는 것을 막아줍니다. 즉 **"발견 즉시 표시"** 하는 것이 큐 안에 중복 원소가 쌓이는 것을 방지하는 핵심 트릭입니다.

```python
for next_index in graph[curr_index]:      # bfs.py:14
    if is_visited[next_index]:            # bfs.py:15
        continue

    queue.append(next_index)              # bfs.py:18
    is_visited[next_index] = True         # bfs.py:19  <- push와 동시에 방문 표시
```

> 참고: `bfs.py:12`의 `# visit process` 주석 자리는 실제 방문 시 수행할 작업(예: 거리 기록, 값 출력 등)을 채워 넣는 자리로 비워져 있습니다. 현재 구현은 `is_visited` 배열만 채우고 `None`을 반환하므로, `test_bfs.py`의 테스트들도 "에러 없이 끝까지 순회하는지"만 검증합니다.

## 4. BFS와 DFS 비교

| 구분 | BFS | DFS |
|---|---|---|
| 자료구조 | 큐 (FIFO) | 스택 (LIFO) 또는 재귀 |
| 탐색 방식 | 가까운 노드부터 레벨 단위로 | 한 방향으로 최대한 깊이 들어갔다가 되돌아옴 |
| 무가중치 그래프 최단 경로 | 보장됨 (처음 방문 시점 = 최단 거리) | 보장되지 않음 |
| 방문 표시 시점(이 저장소 구현 기준) | push할 때 (`bfs.py:19`) | 구현마다 다름 — [`../dfs/README.md`](../dfs/README.md) 참고 |
| 대표 용도 | 최단 경로, 레벨별 탐색 | 경로 존재 여부, 백트래킹, 위상 정렬 |

자세한 비교는 [DFS 문서의 "BFS와 DFS 비교"](../dfs/README.md#4-bfs와-dfs-비교) 섹션도 함께 참고하세요.

## 5. 시간복잡도 / 공간복잡도

| 항목 | 복잡도 | 설명 |
|---|---|---|
| 시간복잡도 | `O(V + E)` | 모든 정점(V)을 한 번씩 큐에서 꺼내고, 모든 간선(E)을 한 번씩 확인 |
| 공간복잡도 | `O(V)` | `is_visited` 배열 + 큐에 최대 V개의 정점이 쌓일 수 있음 |

## 6. 개념 ↔ 코드 대응표

| 개념 | 코드 위치 |
|---|---|
| BFS 진입점 | `bfs()` (`bfs.py:3`) |
| 방문 여부 기록 배열 | `is_visited` (`bfs.py:4`) |
| FIFO 큐 (deque) | `queue = deque([start_index])` (`bfs.py:6`) |
| 큐에서 꺼내기 (다음 처리 대상) | `queue.popleft()` (`bfs.py:10`) |
| 방문 처리(현재는 빈 자리) | `# visit process` (`bfs.py:12`) |
| 인접 노드 순회 | `for next_index in graph[curr_index]:` (`bfs.py:14`) |
| 중복 방문 방지 | `if is_visited[next_index]: continue` (`bfs.py:15-16`) |
| 발견 즉시 큐에 넣고 방문 표시 | `queue.append()` + `is_visited[...] = True` (`bfs.py:18-19`) |
