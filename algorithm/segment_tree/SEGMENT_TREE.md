# 세그먼트 트리 (Segment Tree)

> 구현: [`segment_tree.py`](./segment_tree.py) — `SegmentTree` 클래스

## 1. 왜 세그먼트 트리가 필요한가?

"배열의 `[i, j]` 구간 합(또는 최솟값/최댓값)을 구하라"는 요청이 반복해서 들어오고, 중간중간 배열 값이 바뀌기도 한다고 해봅시다.

| 방법 | 구간 쿼리 | 값 변경(update) |
|---|---|---|
| 매번 구간을 처음부터 다 더하기 | `O(n)` | `O(1)` |
| 미리 누적합(prefix sum) 배열을 만들어두기 | `O(1)` | `O(n)` (뒤따르는 모든 누적합을 다시 계산) |

값이 자주 바뀌지 않는다면 누적합으로 충분하지만, **조회와 갱신이 번갈아 계속 일어나는 상황**에서는 둘 중 하나가 항상 `O(n)`이라 느려집니다.

**세그먼트 트리**는 배열을 이진 트리로 감싸서, 각 노드가 "자신이 담당하는 구간의 계산 결과"를 미리 들고 있게 만듭니다. 그러면 쿼리도 갱신도 트리의 높이인 `O(log n)`만 타고 내려가면 끝납니다 — 두 마리 토끼를 다 잡는 구조입니다.

```
전체 배열 [1, 2, 3, 4, 5]의 합을 구하려면
전체를 훑을 필요 없이, 미리 계산해둔 "부분 구간의 합"들을 몇 개만 조합하면 됩니다.
```

## 2. 트리 구조: 각 노드는 "구간"을 담당한다

`SegmentTree(size, binary_operator=operator.add, identity=0)`(`segment_tree.py:6`)는 리프가 배열의 원소 하나씩을, 내부 노드는 "왼쪽 절반 + 오른쪽 절반을 합친 구간"을 담당하는 완전 이진 트리를 배열(`self.tree`) 위에 만듭니다.

`[1, 2, 3, 4, 5]`(`size=5`)로 만든 합(sum) 세그먼트 트리는 다음과 같은 모양입니다 (괄호 안은 담당 구간, 노드 아래 숫자는 그 구간의 합):

```
                    [0,4]=15
                   /        \
              [0,2]=6        [3,4]=9
              /    \          /    \
        [0,1]=3  [2,2]=3  [3,3]=4  [4,4]=5
        /    \
   [0,0]=1  [1,1]=2
```

리프 노드는 원본 배열의 값(`index`별 원소) 그대로이고, 부모 노드는 항상 "왼쪽 자식 결과 `operator` 오른쪽 자식 결과"입니다. 기본 연산자는 `operator.add`(합)이지만, `min`/`max`를 넘기면 그대로 구간 최솟값/최댓값 트리가 됩니다 — 트리 구조는 완전히 동일하고 **노드를 합치는 연산만 바뀝니다** (`identity`도 연산에 맞게 함께 바뀌어야 합니다: 합이면 `0`, 최솟값이면 `float('inf')`, 최댓값이면 `float('-inf')`).

## 3. 배열 위에서의 인덱스 규칙

포인터 대신 배열 인덱스로 트리를 표현합니다 (힙과 같은 방식):

```python
left_node  = node * 2 + 1
right_node = left_node + 1
mid_index  = (node_left_index + node_right_index) // 2
```

생성자(`segment_tree.py:13-16`)는 `size`를 담을 수 있는 **2의 거듭제곱** 크기(`base_size`)를 구해 배열 크기(`tree_size = base_size * 2 - 1`)를 미리 확보해둡니다. 실제 구간 분할은 `size`를 그대로 쓰므로(2의 거듭제곱이 아니어도 동작), `base_size`/`base_index`는 "노드 인덱스가 배열 범위를 벗어나지 않도록" 충분한 공간을 미리 잡아두는 용도입니다.

## 4. 갱신(`update`): 리프를 고치고 조상들을 다시 계산

`update(target_index, value)`(`segment_tree.py:20-21`)는 리프까지 재귀로 내려가 값을 바꾼 뒤, **돌아오는 길에** 지나온 조상 노드들을 자식 두 개로 다시 계산합니다(`segment_tree.py:38-43`).

`index 2`의 값을 `3 → 100`으로 바꾸면:

```
                    [0,4]=15 → 112            ← 3단계: 루트도 다시 계산
                   /        \
              [0,2]=6 → 103    [3,4]=9        ← 2단계: 경로상의 부모도 다시 계산
              /    \
        [0,1]=3  [2,2]=3 → 100                ← 1단계: 리프 값 변경
        /    \
   [0,0]=1  [1,1]=2
```

값을 바꾼 리프에서 루트까지 이어지는 경로 위의 노드들만 다시 계산하면 되므로, 트리 높이만큼인 `O(log n)`에 끝납니다. 나머지 노드(`[3,4]`, `[0,1]` 등)는 건드릴 필요조차 없습니다.

## 5. 조회(`query`): 구간을 O(log n)개의 "이미 계산된 조각"으로 쪼개기

`query(start_index, end_index)`(`segment_tree.py:64-65`)는 루트에서 시작해 세 가지 경우로 나눠 재귀합니다(`segment_tree.py:68-89`):

1. **완전히 벗어남** (`start > node_right` 또는 `end < node_left`) → 이 노드는 버림(`None` 반환, 계산에서 제외)
2. **완전히 포함됨** (`start <= node_left` 이고 `node_right <= end`) → 이 노드에 미리 계산된 값을 그대로 사용, 더 내려가지 않음
3. **일부만 겹침** → 왼쪽/오른쪽 자식으로 나눠 재귀한 뒤 결과를 합침

`[1, 2, 3, 4, 5]`에서 `query(1, 3)`(값 `2+3+4=9`)을 요청하면:

```
                    [0,4]                     ← 일부만 겹침 → 양쪽으로 내려감
                   /        \
              [0,2]           [3,4]           ← 둘 다 일부만 겹침 → 더 내려감
              /    \          /    \
        [0,1]  ✔[2,2]=3   ✔[3,3]=4   [4,4]    ← [2,2], [3,3]은 완전 포함 → 그대로 사용
        /    \
   [0,0]  ✔[1,1]=2                             ← [1,1]도 완전 포함 → 그대로 사용

필요한 조각: [1,1]=2, [2,2]=3, [3,3]=4  →  2 + 3 + 4 = 9
```

배열 전체(`5`개 리프)를 다 보는 대신, **`O(log n)`개의 이미 계산된 조각만 조합**해서 답을 구합니다. 이것이 세그먼트 트리가 구간 쿼리를 빠르게 처리하는 핵심 원리입니다.

> 참고: `segment_tree.py`에는 반복문(loop) 버전인 `__update_by_loop`(`segment_tree.py:46-60`), `__query_by_loop`(`segment_tree.py:91-109`)도 함께 구현되어 있지만, 현재 `update()`/`query()`는 재귀 버전만 호출합니다 — 반복문 버전은 대안 구현으로 코드에 남아있는 상태입니다.

## 6. 시간/공간복잡도

| 연산 | 시간복잡도 | 설명 |
|---|---|---|
| `update()` | `O(log n)` | 리프까지 내려갔다가 조상만 다시 계산 |
| `query()` | `O(log n)` | 최대 `O(log n)`개의 노드로 구간을 쪼갬 |
| 배열 전체로 트리 만들기 | `O(n log n)` | 원소 `n`개를 `update()`로 하나씩 채우는 경우 (`n × O(log n)`) |
| 공간 | `O(n)` | `tree_size = 2 × (n 이상인 최소 2의 거듭제곱) - 1`, 대략 `4n` 이내 |

## 7. 개념 ↔ 코드 대응표

| 개념 | 코드 위치 |
|---|---|
| 트리 생성 (연산자/항등원 주입) | `SegmentTree.__init__` (`segment_tree.py:6`) |
| 배열 크기 → 트리 배열 크기 계산 | `base_size`, `base_index`, `tree_size` (`segment_tree.py:13-15`) |
| 리프 → 루트 방향, 값 변경 | `update()` → `__update_by_recursive()` (`segment_tree.py:20`, `24`) |
| 자식 두 개를 합쳐 부모 값 계산 | `self.operator(self.tree[left_node], self.tree[right_node])` (`segment_tree.py:39`) |
| 구간을 완전 포함/완전 배제/부분 겹침으로 분기 | `__query_by_recursive()` (`segment_tree.py:68-89`) |
| 커스텀 연산자로 min/max 트리 만들기 | `SegmentTree(size, min, float('inf'))` 등 (테스트 참고) |

## 8. 관련 테스트

```bash
pytest tests/segment_tree/test_segment_tree.py -v
```
